# Contrato de seguridad y permisos pendientes de prueba

Revisión adicional: la API REST puede devolver 202 y una URL de seguimiento regional de operación. No se ha comprobado el polling de Az.Compute con una asignación limitada a VM; no se deduce que precise un permiso extra ni se concede preventivamente. Un error de autorización durante ese seguimiento requiere la misma detención y aprobación que cualquier 403. [Contrato REST y respuesta 202](https://learn.microsoft.com/en-us/rest/api/compute/virtual-machines/run-command?view=rest-compute-2025-04-01).

El único destino ejecutable se construye desde una política administrativa cerrada: suscripción GUID, `rg-h4-observabilidad`, `vm-h4-iis`, `H4LabSite`, `H4LabPool` y HTTP loopback fijo. `enabled=false` en el ejemplo. No aceptar rutas, comandos, URLs, credenciales, nombres de pool o destinos desde el payload.

`Read-H4Alert` procesa `WebhookData.RequestBody`, limita tamaño a 64 KiB y exige Common Alert Schema, essentials v1, señal Log, regla exacta, workspace exacto, un solo target y dimensiones únicas `_ResourceId`/`Site`/`Pool`. El ID completo de regla se contrasta cuando existe. Rechaza alertas antiguas (>15 minutos), futuras (>60 segundos), incompletas o inconsistentes. Solo **Fired** permite continuar; **Resolved** no actúa. Activated significa activada en esquemas antiguos: se rechaza al no existir un adaptador legacy aprobado. No se interpreta como Fired por semejanza de texto. El destino workspace más dimensión VM corresponde a la configuración de alerta elegida, no se acepta cualquier combinación. [Esquema oficial](https://learn.microsoft.com/en-us/azure/azure-monitor/alerts/alerts-common-schema).

Esto valida alcance, **no autentica al emisor**. La URL del webhook de Automation actúa como secreto portador; quien la conoce puede iniciar jobs. El usuario acepta este riesgo solo en el laboratorio temporal. Vigencia propuesta: hasta el cierre del mismo día, máximo seis horas; habilitar al final y deshabilitar primero al cerrar. No copiar URL a terminal, variables de prueba, repo, chat, capturas ni transcripción. Vincularla solo mediante Portal. Evitar cuerpos/headers secretos: Automation registra parámetros de entrada de jobs; el script no imprime WebhookData ni excepciones originales, pero no controla toda la retención de la plataforma. RBAC de administradores y acceso a jobs debe restringirse. [Webhook y seguridad](https://learn.microsoft.com/en-us/azure/automation/automation-webhooks).

Identidad administrada System Assigned de `aa-h4-remediation`. Rol propuesto `H4-RunCommand-LabVM`:

| Acción | Motivo |
|---|---|
| `Microsoft.Compute/virtualMachines/runCommand/action` | Permiso documentado para ejecutar Action Run Command |
| `Microsoft.Compute/virtualMachines/read` | Lectura de VM reservada al diagnóstico de validación; el código no enumera VMs |
| `Microsoft.Compute/virtualMachines/instanceView/read` | Verificar estado del agente en una futura comprobación; el código no enumera instancias |

La definición permite asignar el rol dentro del RG; la **asignación** se hace exclusivamente en el ID de `vm-h4-iis`, nunca a RG o suscripción. `AssignableScopes` no concede permisos por sí solo. No añadir Contributor, comodines, `virtualMachines/write`, extensiones/write ni permisos de catálogo. La identidad no recibe acceso a otros recursos ni a la administración del propio runbook.

**Comprobación documental realizada:** Microsoft distingue ejecutar (`virtualMachines/runCommand/action`) de listar/consultar el catálogo (`locations/runCommands/read` a nivel de suscripción). Se usa `Invoke-AzVMRunCommand` con nombre/RG y CommandId fijo, sin listar catálogo. No se documenta aquí un permiso adicional de catálogo para esa invocación. Esto **no demuestra** suficiencia efectiva del rol en Azure ni todas las llamadas internas de una versión de Az.Compute. La autenticación y seguimiento del job se validarán con versiones registradas. Si aparece un 403, conservar solo operación denegada y alcance redactados, detenerse y solicitar aprobación; no ampliar automáticamente. [Permisos Run Command](https://learn.microsoft.com/en-us/azure/virtual-machines/windows/run-command), [parámetros del cmdlet](https://learn.microsoft.com/en-us/powershell/module/az.compute/invoke-azvmruncommand).

Action Run Command usa SYSTEM, admite una ejecución simultánea, tiene salida limitada a 4096 bytes y no permite cancelar una ejecución en curso. Por eso se devuelve JSON breve, no se inicia otro comando si hay resultado de transporte indeterminado, y los conflictos fallan con escalamiento. El permiso permite ejecutar código arbitrario en la VM: **RBAC no lo restringe a Start-WebAppPool**. La restricción depende de proteger runbook, módulo, política y archivos del invitado. Reutilizar este rol en una VM real estaría fuera de alcance. Se necesita salida HTTPS del agente; no puertos entrantes públicos. [Restricciones documentadas](https://learn.microsoft.com/en-us/azure/virtual-machines/windows/run-command).

El bloqueo de aplicación se mantiene en el invitado, donde se produce el efecto, y complementa la exclusión de Run Command. Ledger preexistente, sustitución atómica con flush antes de iniciar el pool, conservación de intentos fallidos y deduplicación por alerta. Un crash deja Pending y obliga a revisión humana; no se intenta deducir éxito ni renovar el presupuesto. Capacidad máxima 500 incidentes, sin poda automática. Directorio y ancestros sin reparse points; ACL SYSTEM/Administradores, sin escritura del pool ni de la cuenta del sondeo. Las ACL deben verificarse en Server antes de activarlo; protección frente a un administrador hostil no está garantizada.

Alerta B consume Diagnostic Settings JobLogs/JobStreams, estados Failed/Suspended o JSON `AttemptsExhausted`/`EscalationRequired`. Envío solo a `ag-h4-human`; nunca al runbook. Los datos de Automation pueden tardar hasta 15 minutos en llegar a Log Analytics, por lo que B no es un temporizador inmediato ni prueba de ausencia de jobs atascados. Validar columnas reales y salida JSON completa antes de activarla. [Esquema y consultas de jobs](https://learn.microsoft.com/en-us/azure/automation/automation-manage-send-joblogs-log-analytics).
